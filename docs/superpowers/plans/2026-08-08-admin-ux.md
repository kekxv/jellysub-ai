# Admin UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task.

**Goal:** Turn the existing administration page into a task-first operational console that clearly communicates queue state, stage progress, failures, and next actions.

**Architecture:** Keep the existing single-page HTML/CSS/JS stack and APIs. Add a derived client-side task summary and active queue panel above the video library, enrich task cards with deterministic stage/progress presentation, and use CSS layout primitives matching the existing light indigo design system.

**Tech Stack:** Static HTML, CSS, vanilla JavaScript, FastAPI task APIs, pytest source-contract tests.

## Global Constraints

- Preserve the existing color tokens, static asset structure, and authenticated API endpoints.
- Render all task-derived text through `escHtml`; do not introduce unescaped `innerHTML` data paths.
- The responsive view must prioritize queue status and the primary task action.
