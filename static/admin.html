JELLYFIN → JELLYSUB-AI

新媒体入库，自动处理字幕

完成连接、路径映射与签名设置后，Jellyfin 即可自动提交任务。在任务中心跟踪处理进度并查看字幕。

配置 Jellyfin 连接 →
01

准备连接与媒体目录

在「系统设置 → Jellyfin 连接」填写服务器地址与 API Key，并配置路径映射。例如：

/media/movies映射到本服务可访问的/mnt/movies

在「媒体与语言」将 /mnt/movies 加入视频库监控目录，选择目标语言。目录需允许写入字幕；Docker 部署时填写容器内路径。

02

选择自动处理方式

语音识别
从音轨生成字幕。沿用原规则，视频有内置字幕时跳过。
优先翻译字幕，自动回退
优先同名外挂字幕，其次内置文本字幕；没有可用文本字幕时使用语音识别。
仅翻译字幕
只处理已有文本字幕，没有来源则跳过，不启动语音识别。

翻译支持 SRT、VTT、ASS、SSA 和内置文本字幕；PGS/DVD 等图形字幕不能直接翻译。三种模式在已有有效目标语言外挂字幕时均跳过。

03

配置请求签名

在服务的环境变量或 .env 中设置随机的 WEBHOOK_SECRET，重启服务。Docker 部署需将该变量传入容器。

openssl rand -hex 32
# 将生成值配置为 WEBHOOK_SECRET，然后重启服务

发送方使用相同密钥，对最终发送的原始 JSON 字节计算 HMAC-SHA256，将 64 位十六进制结果放入 X-Jellyfin-Signature 请求头。

签名随请求内容变化，不能填成固定 Header。若插件无法动态签名，需要经过支持 HMAC 的中间发送器转发。未设置密钥时接口返回 503。

04

连接 Jellyfin Webhook

在 Jellyfin 插件目录安装 Webhook 并重启。添加 Generic Webhook 通知目标，启用它，使用 POST 和 application/json。

/webhook

地址需能被 Jellyfin 或中间发送器访问；反向代理部署时使用其对外地址。触发事件选择 Item Added（新增媒体），仅电影与剧集会被处理。

{
  "ItemType": "Movie",
  "ItemId": "Jellyfin 中实际的媒体 ID",
  "Name": "电影名称",
  "Path": "/media/movies/电影名称.mkv"
}

路径使用 Jellyfin 所见的媒体路径；ItemType 为 Movie 或 Episode。

05

验证签名与任务处理

可先用下面的 Python 示例测试接收端。将媒体 ID、路径和地址替换为真实值，在终端环境中设置同一个 WEBHOOK_SECRET。测试会实际提交任务；成功后去任务中心查看。

import hashlib, hmac, json, os, urllib.request

payload = {"ItemType": "Movie", "ItemId": "真实媒体ID",
           "Name": "测试电影", "Path": "/media/movies/电影名称.mkv"}
body = json.dumps(payload, ensure_ascii=False).encode("utf-8")
signature = hmac.new(os.environ["WEBHOOK_SECRET"].encode(),
                     body, hashlib.sha256).hexdigest()
request = urllib.request.Request(
    "http://127.0.0.1:8000/webhook", data=body, method="POST",
    headers={"Content-Type": "application/json",
             "X-Jellyfin-Signature": signature})
with urllib.request.urlopen(request) as response:
    print(response.read().decode())
